# 프로그래머블 프로토콜 엔진 v0.2

[추론] §§1–8은 v0.1 단독 모드를 정의한다. §9는 리셋 시 선택하는 두 컨텍스트 모드의 추가 규칙을 정의한다. 두 모드가 공유하는 ISA와 프레임 기본 형식은 §§3–6을 따른다. §9가 다르게 정의한 동작은 해당 모드에서 §9를 적용한다.

## §1. 외부 인터페이스와 상태

프로그램 메모리는 16비트×256워드, 단일 포트다. PC 8비트, 이미지 길이 9비트(1~256), 시간 T 16비트, 루프 LC 8비트, 송신 OSR와 수신 ISR은 각각 8비트다. 동시 송수신에서 한쪽 시프트가 다른 쪽을 바꾸지 않는다. WAIT 결과는 NONE·OK·TIMEOUT 중 하나다.

| TT 신호 | 책임 |
|---|---|
| clk, rst_n, ena | 상승 에지 실행, active-low 리셋, 선택. ui·uo·uio 버스는 각각 8비트다. |
| ui_in | [3:0] 호스트 니블, [4] REQ 토글. 해제 중 [7:5]로 §9.1의 모드를 선택한다. 단독 모드를 쓰는 v0.1 호스트는 000을 사용한다. 듀얼 프레임에서는 [6]이 §9.4의 대상이다. |
| uo_out | [3:0] 응답 니블, [4] ACK 토글, [5] READY(완전한 이미지), [6] RUNNING, [7] FAULT. |
| uio_in, uio_out, uio_oe | 프로그램용 입력·출력 데이터·출력 인에이블. OE 비트 1은 해당 핀 구동을 뜻한다. |

## §2. 클록과 관측 경계

- 에지 **직전** 값으로 판정하고, 에지 **직후** 안정된 상태를 기록한다. K는 RUN을 수락한 에지, F는 SRAM 읽기를 요청한 에지, S는 그 명령의 첫 실행, R은 완료된 명령의 효과를 한 번 반영하는 에지다.
- v0.1은 비중첩 동기 읽기를 사용한다. 첫 F=K+1, S=F+1이다. 정상 실행이 계속되면 다음 F=R+1이다. 대기 중에는 명령과 PC를 유지한다. 실제 매크로가 이 인출 지연을 만족하는지 모델과 타이밍으로 검증한다. 만족하지 못하면 명세 버전과 프로그램 주기표를 함께 개정한다.
- 프로토콜 입력은 핀마다 2FF를 거친다. 디지털 모델에서 매 상승 에지에 1단은 외부 핀, 2단은 이전 1단, 이력은 이전 2단을 저장한다. 실행부는 에지 직전 2단 값과 이력을 비교한다. 첫 유효 2단 표본으로 이력을 초기화하며 그 첫 표본에서는 사건을 만들지 않는다. 이력은 WAIT 진입이나 FIFO stall로 지우지 않는다. HIGH·LOW 각 3클록 이상과 입력 위상 스윕은 초기 시험 범위다. 실리콘에서 임의 펄스 포착이나 정확히 2클록의 지연을 보장하지 않는다.
- RTL 모듈 경계의 검증용 관측 이름은 `exec_start, retire, pc, tx_pop, rx_push, tx_count, rx_count`다. 앞의 두 신호는 해당 에지의 S·R 펄스이며 HALT도 은퇴한다. fault·STOP에는 retire가 없다. pc와 점유량은 에지 직후 값, tx_pop/rx_push는 엔진 측 실제 수락 펄스다. ISS는 같은 외부 입력으로 이 값을 독립 계산한다. GLS에서는 보존된 외부 핀·호스트 응답을 사용한다.

활성화된 동기 명령 읽기의 관측 신호는 최상위 `instruction[15:0]`이며 `pe_sram.dout`에 해당한다. formal 검사기는 `exec_start`에서 이 워드의 opcode를 기록하고 해당 명령의 `retire`, fault 또는 STOP까지 그 값을 보관해 비교한다.

## §3. ISA와 출력

워드 [15:11]은 opcode, [10:0]은 인자다. 표에 없는 opcode와 사용하지 않는 인자 비트의 1은 fault다. 정상적인 기본 다음 주소는 PC+1이다. 선택한 다음 주소를 9비트 이상으로 계산해 길이와 비교한다. HALT 외에는 S에서 이를 먼저 검사해 범위 밖이면 어떤 명령 부작용도 없이 fault 처리한다. 취하지 않는 분기의 목표 주소는 검사하지 않는다.

| Opcode (hex) | 명령 | 피연산자와 R 직후 결과 |
|---|---|---|
| 00 | HALT | 인자 0. 현재 PC 유지, 정상 정지. |
| 01, 02 | DATA, OE | [7:0] 즉시값을 각각 준비 데이터·준비 OE에 쓴다. 외부 핀은 유지한다. |
| 03 | COMMIT | [7:0] 마스크가 1인 비트에서 활성 데이터·OE를 두 준비값으로 같은 R에 바꾼다. 나머지는 유지한다. |
| 04, 05 | TLO, THI | [7:0]으로 T의 하위·상위 바이트만 각각 쓴다. |
| 06 | WAIT | 핀 [2:0], [4:3]은 LOW/HIGH/RISE/FALL = 0/1/2/3, [5]=1이면 무한 대기. §4를 따른다. |
| 07 | DELAY | 인자 0. §4에서 D는 S 직전의 T다. |
| 08, 09 | SHIN, SHOUT | 핀 [2:0], [3]=0은 MSB 우선, 1은 LSB 우선. SHIN은 R 직전 동기화 표본을 ISR에 넣는다. MSB 우선이면 왼쪽으로 밀고 bit0, LSB 우선이면 오른쪽으로 밀고 bit7에 넣는다. SHOUT은 OSR의 이전 bit7 또는 bit0을 선택한 핀의 활성·준비 데이터에 쓰고, 각각 왼쪽 또는 오른쪽으로 밀어 빈 자리에 0을 넣는다. OE는 유지한다. |
| 0A | BR | [9:8]의 0/1/2/3은 각각 무조건/WAIT OK/WAIT TIMEOUT/LC=0, [7:0]은 절대 워드 주소다. 조건 거짓이면 순차 진행한다. |
| 0B, 0C | LSET, DJNZ | LSET은 [7:0]을 LC에 쓴다. DJNZ는 LC가 양수면 1 감소시킨다. 새 LC가 양수일 때만 [7:0]으로 분기한다. 이전 LC=0이면 0을 유지하고 순차 진행한다. |
| 0D, 0E | PUSH, PULL | 인자 0. 각각 ISR을 RX에 복사하거나 TX의 가장 오래된 바이트를 OSR로 꺼낸다. §5를 따른다. |
| 0F | SRIMM | [7:0] 즉시값을 OSR에 쓴다. ISR은 유지한다. |

단순 명령은 R=S다. 실행 중 활성 OE가 변하는 경우는 COMMIT과 §6의 안전 상태 전환뿐이다. 핀의 능동 구동이 필요하면 프로그램이 OE도 준비해야 한다.

## §4. WAIT와 DELAY 경계

WAIT는 S 자체를 포함해 각 클록의 실행부 관측값을 검사한다. 이미 참인 레벨과 S에서 처음 보이는 에지는 즉시 성공한다. S 전의 사건은 사용하지 않는다. 유한 대기의 마지막 에지는 **N=S+T**다. N에서도 성공이 타임아웃에 우선한다. 성공 또는 만료 시에만 WAIT 결과와 PC를 갱신한다. WAIT 외의 명령은 결과를 유지한다(§6 초기화 제외). 무한 대기에는 만료가 없으며 STOP·리셋으로 빠져나올 수 있다.

| 실행부에서 보인 입력 | 결과 |
|---|---|
| RISE가 S−1에서만 보이고 이후 HIGH 유지 | RISE 명령에는 새 사건이 없다. HIGH 명령은 S에 성공한다. |
| RISE가 S에서만 보임 | S에서 RISE 성공. S는 실행과 첫 판정이 겹치는 에지다. |
| 마지막 N에서 처음 보임 / N+1에서 처음 보임 | 각각 N에서 성공 / N에서 타임아웃. N 직후의 검출값 갱신은 N 판정에 반영되지 않는다. |

T=0은 S 한 번, T=1은 S와 S+1 두 번 검사한다. DELAY는 **R=S+D**다. D=0은 S, D=1은 S+1에 완료하며 새 명령의 인출은 각각 그다음 에지다.

<a id="s5"></a>
## §5. 호스트 FIFO

TX·RX는 각각 깊이 4의 바이트 FIFO다. 읽기·쓰기 허가는 에지 직전 점유량으로 정한다. 빈 큐에서 같은 에지에 쓰더라도 읽기는 거부한다. 가득 찬 큐에서 같은 에지에 읽더라도 쓰기는 거부한다. 중간 점유량이면 동시에 가장 오래된 항목을 읽고 새 항목을 뒤에 붙이며 점유량은 같다. 엔진 PUSH(full)·PULL(empty)는 해당 명령과 PC·플래그·레지스터·외부 핀을 보존하고 다음 클록마다 재시도한다. 호스트의 허가된 반대편 전송은 계속된다. 엔진은 첫 수락 에지에 한 번만 은퇴한다. 호스트의 막힌 요청은 §6의 재시도 응답으로 종료한다.

독립 formal 검증용 모듈 경계 `pe_fifo`의 입력은 `clk`, `reset_n`(active-low), `clear`(동기 active-high), `push`, `pop`, `data_in[7:0]`이고 출력은 `head[7:0]`, `count[2:0]`이다. 리셋이 최우선이고 이어서 clear가 큐를 비운다. 둘 다 비활성이면 상승 에지 직전 count로 push·pop 요청을 판정한다. head는 count가 양수일 때 가장 오래된 데이터이며 빈 큐에서는 값이 미정이다.

<a id="s6"></a>
## §6. 고정 로더·리셋·정지

호스트는 니블을 먼저 안정시키고 REQ를 토글한 뒤 ACK가 일치할 때까지 니블을 유지한다. REQ는 2FF를 거친다. 로더는 에지 직전 동기화 REQ≠ACK일 때 니블을 한 번 수락하며 그 에지 직후 ACK를 해당 REQ로 맞춘다. 다음 요청 전까지 응답은 안정된다. 바이트는 **상위 니블 먼저**, 16비트 길이·워드는 **하위 바이트 먼저** 보낸다. 호스트는 응답을 읽은 뒤 다음 전송을 시작한다.

| 명령 바이트 | 페이로드 / 수락 효과 |
|---|---|
| 00 STATUS | 항상 가능. bits [0..5]에 TX 여유, RX 유효, READY, RUNNING, FAULT, LOADING의 에지 직전 값을 반환한다. [7:6]=0. |
| 01 BEGIN | 길이 2바이트. RUNNING=0(LOADING·FAULT 포함)이고 길이가 유효할 때 마지막 페이로드 니블에서 새 적재를 시작한다. 이때 기존 READY·FAULT, 양쪽 FIFO, 쓰기 주소·합·개수를 초기화한다. 길이 1~256만 허용하며 유효한 동안 LOADING=1이다. |
| 02 WRITE | 워드 2바이트. LOADING에서만 다음 순차 주소에 쓰고 개수와 합을 갱신한다. 합은 16비트 워드 합 mod 65536이다. |
| 03 END | 합 2바이트. LOADING에서 선언 길이와 개수, 합이 모두 맞으면 LOADING=0, READY=1이다. |
| 04 RUN | 정지·READY·무오류에서만 수락한다. PC·출력·준비값·OSR·ISR·T·LC=0, WAIT 결과=NONE. FIFO·입력 이력을 보존하고 RUNNING=1. READY는 계속 1이다. |
| 05 STOP | 모든 상태에서 수락. 정지하고 PC·출력·준비값·OSR·ISR·T·LC와 양쪽 FIFO를 0, WAIT 결과를 NONE으로 한다. 부분 이미지는 폐기하고 LOADING=0으로 한다. 완성 이미지의 READY, 기존 FAULT는 보존한다. |
| 06 TX, 07 RX | TX는 입력 1바이트를 TX에 넣는다(READY·무오류). RX는 READY에서 RX의 가장 오래된 바이트를 명령 수락 에지에 한 번만 꺼내 응답에 보관한다. |

중간 요청 니블의 응답은 0이다. 명령의 마지막 니블에서 상태와 페이로드를 판정해 응답 코드 0=성공, 1=FIFO 재시도, 2=상태 거절, 3=형식/길이/검산 오류를 보낸다. STATUS와 RX의 성공 뒤에만 추가 더미 니블 두 개를 보내 결과의 상위·하위 니블을 읽는다(호스트는 0 전송, 로더는 값 무시). 허용 상태를 먼저 검사하며 거절된 명령은 정의된 페이로드만 소비한다. 잘못된 BEGIN 길이, LOADING에서 초과 WRITE 또는 END 불일치는 코드를 3으로 하고 LOADING·READY를 지운다. 알 수 없는 명령은 코드 3으로 끝나며 기존 이미지 상태를 유지한다. 이 세 적재 오류는 기존 FAULT·FIFO를 보존한다. 로더 오류 응답 자체는 FAULT를 세우지 않는다. 중단된 니블 프레임은 리셋으로 복구한다. STOP은 명령 경계에서 해석한다.

리셋(assert rst_n=0) 또는 선택 해제(ena=0)는 최우선이다. OE·출력·호스트 응답·ACK·READY·RUNNING·FAULT·LOADING·PC·레지스터·FIFO 점유/포인터·로더 프레임·동기화 이력 유효 표시를 0, WAIT 결과를 NONE으로 만든다. SRAM 내용은 초기값에 의존하지 않는다. ena와 rst_n이 모두 1이 된 뒤 연속 두 상승 에지를 내부 리셋 해제에 사용하고 세 번째부터 정상 처리한다. 호스트는 해제 동안 REQ=0을 유지하고 재선택 후 이미지를 다시 적재한다.

정상 HALT는 RUNNING과 활성 OE를 0으로 하고 PC·출력 데이터·이미지·FIFO를 유지한다. 엔진 fault는 해당 PC와 기존 레지스터를 보존하고 FAULT=1, RUNNING=0, 활성 OE=0으로 하며 해당 명령은 은퇴하지 않는다. 새 BEGIN으로 복구한다. STOP 수락은 같은 클록의 엔진 명령에 우선한다. 나머지 허가된 호스트 FIFO 전송은 엔진과 독립이다. SRAM 쓰기는 LOADING에서만, 읽기는 RUNNING에서만 발생한다.

## §8. 수용 조건

[추론] 50 MHz 가정에서 UART TX/RX는 8N1·115200 baud(LSB 먼저), SPI 마스터는 모드 0~3·SCK 1 MHz를 우선 목표로 한다. 예제 핀은 UART TX/RX=uio[0]/[1], SPI SCK/MOSI/MISO/CS_n=uio[0]/[1]/[2]/[3]이다. UART TX 비트 폭 오차 ≤1%, RX 외부 baud −2/0/+2%와 위상 0·¼·½·¾ 클록에서 256종 정상 바이트 복구, 정지 LOW 프레임 미입큐를 검사한다. UART 위상 0은 수신 클록의 상승 에지에서 표본 채취 직후(0+)다. SPI 예제는 MSB 우선이다. CPOL이 유휴 레벨을, CPHA=0/1이 각각 선행/후행 에지를 샘플 에지로 정한다. CPHA=0의 첫 MOSI 비트는 첫 선행 에지 전에 준비한다. 나머지 비트 및 CPHA=1의 첫 비트는 해당 변경 에지부터 다음 샘플 에지 2클록 전까지 구동한다. MOSI는 샘플 에지 전후 각각 2클록 이상 안정돼야 한다. 독립 BFM은 샘플 에지의 핀값으로 복원한다. MISO도 BFM에서 샘플 에지 전후 각각 3클록 이상 안정시키고, 프로그램은 해당 비트가 동기화 2단에 보이는 구간에 SHIN을 실행한다. 반주기 25±1클록, CS setup·hold 각각 ≥25클록, 서로 다른 MOSI/MISO 바이트를 동시에 복원해야 한다.

14일차 세 조건은 SRAM 포함 GDS의 공식 precheck, 독립 BFM의 UART TX 통과, 배선 후 면적 점유율 ≤40%다. 점유율은 100×(실제 엔진·FIFO·로더 표준셀과 클록 트리 면적 + SRAM 등 하드 매크로 외곽 면적)/동일 8×4 DEF·ODB 코어 사각형 면적이다. filler·tap·endcap·decap은 제외하고 매크로는 한 번 센다. 래치 대안은 SRAM 통과로 집계하지 않는다. 증거·검출률·동결 절차는 [검증 계획](../docs/verification_plan.md)에 둔다. [미실행] 실제 매크로, WNS, 면적 및 프로토콜 속도의 실측값은 아직 없다.

## §9. 두 컨텍스트 모드

### §9.1. 모드 선택과 에지 번호

[추론] E1은 에지 직전 rst_n과 ena가 모두 1인 첫 상승 에지다. 호스트는 리셋 또는 선택 해제 중부터 E3까지 REQ=0, ui[7:5]를 고정한다. 각 모드 비트는 E1, E2에서 독립적으로 2단을 통과한다. E3에서 에지 직전 2단 값이 001이면 듀얼, 나머지 일곱 값이면 단독을 선택한다. 듀얼로 재진입할 때는 직전 프레임의 대상이 B였더라도 이 구간의 ui[6]을 0으로 되돌려 001을 만든다. 이후 리셋·선택 해제까지 모드를 보존한다. 단독은 프레임 중 ui[7:5]를 무시하며 v0.1 §§1–8의 전체 이미지·핀·클록 동작을 유지한다.

[추론] 듀얼에서 **E 번호 자체**가 짝수면 A 인출·B 실행, 홀수면 B 인출·A 실행이다. E1=1, E3=3으로 세며 정상 처리는 E3부터 허용한다. RUN·STOP·두 컨텍스트가 모두 쉬는 기간에도 홀짝은 진행한다. 빈 슬롯은 그대로 둔다. 대상 X의 RUN 수락 K 또는 이전 명령 은퇴 R보다 엄격히 뒤인 첫 X 인출 슬롯이 F이고 S=F+1이다. 회수한 워드는 요청 때의 대상과 유효 여부로 식별한다. 대상 STOP, fault, 리셋은 남은 명령과 판정을 취소한다. 대상 STOP 수락 에지에는 그 대상의 인출·실행 시작·은퇴를 모두 억제한다. 같은 에지의 상대 요청이나 응답은 유효할 수 있다. 지연된 응답이 재시작된 컨텍스트에 영향을 주지 않는다.

### §9.2. 프로그램·핀·실행 상태

[추론] A=0은 물리 워드 0–127과 uio[7:4], B=1은 워드 128–255와 uio[3:0]을 소유한다. PC와 분기 목적지는 프로그램 시작점 기준이다. BEGIN 길이 1–128을 허용한다. 선택된 다음 주소를 잘라내기 전에 길이와 비교한다. HALT 예외와 미선택 분기 처리에는 v0.1 §3을 적용한다. 다른 컨텍스트 주소로 순환할 수 없다.

[추론] PC·OSR·ISR·T·LC·WAIT 결과·준비/활성 출력·상태와 깊이 4인 TX/RX FIFO 한 쌍은 각각 독립이다. 입력 이력은 공유하며 WAIT·SHIN은 8핀 중 어느 핀이나 읽을 수 있다. DATA·OE는 8비트를 준비할 수 있다. COMMIT 마스크에 비소유 비트가 하나라도 있거나 SHOUT이 비소유 핀을 선택하면 대상만 fault 처리한다. 그 명령의 쓰기·시프트·은퇴는 없다. 최상위 출력 데이터와 OE는 각각 A의 상위 4비트, B의 하위 4비트를 결합한다. OE가 0이어도 출력 데이터는 관측할 수 있다. HALT·fault는 그 대상의 활성 OE를 0으로 하고 데이터를 유지한다. STOP은 그 대상의 출력 데이터와 OE를 모두 지운다. RUN·BEGIN·STOP의 각 초기화는 v0.1 §6이 해당 명령에서 바꾸는 대상 상태·FIFO·소유 핀에만 적용한다. 상대 컨텍스트의 정상 인출·실행·호스트 동작은 같은 에지에도 진행한다.

### §9.3. 대기와 FIFO의 시간 단위

[추론] S부터 매 상승 에지의 직전 동기화 표본과 이력을 관측한다. 상승 에지는 이전 표본 0, 현재 표본 1일 때 한 번 인정한다. 유한 WAIT의 마지막 허용 에지는 N=S+T다. 첫 성공이 기한과 겹치면 성공이다. 성공이 없으면 d=N에 타임아웃을 결정한다. 처음 결정된 결과를 d에 기억하고 d 이상인 첫 자기 실행 슬롯 R에서 한 번만 공개한다. 그 전까지 PC와 외부에서 보이는 WAIT 결과는 유지한다. R을 기다리는 동안 새 입력은 결정을 덮어쓰지 못한다. STOP이 d 또는 R에 수락되면 기다리던 명령은 은퇴하지 않는다. 두 WAIT가 같은 에지에 판정될 수 있다. 은퇴 기회는 각자의 슬롯에 온다.

[추론] DELAY는 R=S+D+(D mod 2)다. D=0, 1, 2, 65535의 경과 클록은 각각 0, 2, 2, 65536이다. PUSH·PULL은 자기 실행 슬롯마다 에지 직전 자기 FIFO 점유량으로 재시도한다. 호스트 전송은 해당 대상의 슬롯을 기다리지 않는다. 동일 FIFO에 대한 동시 요청에는 v0.1 §5를 적용한다. 대상 STOP·리셋이 우선한다.

### §9.4. 고정 로더

[추론] 호스트는 각 명령·페이로드 니블과 그 대상 ui[6]을 REQ 토글 전에 안정시키고 ACK까지 유지한다. 첫 명령 니블 수락 때 고른 표시 대상 L은 그 에지 직후 바뀌며 다음 첫 니블까지 유지한다. 나중에 프레임이 거절되어도 이 선택은 유지한다. 이후 명령·페이로드 니블 수락 에지에서 ui[6]이 한 번이라도 다르면 오류를 기억한다. 실제 명령 바이트가 정한 페이로드를 끝까지 소비하고 코드 3을 준다. 그 프레임의 SRAM·상태·FIFO 효과는 없다. 유효 프레임에서 부작용은 최종 명령/페이로드 니블 수락 에지에 생긴다. 성공한 RX는 바로 이 에지에 한 번만 pop한다. STATUS/RX 더미 두 니블에서는 선택선과 입력 데이터를 무시하고 보관된 값을 반환한다. 다음 첫 니블까지 uo[7:5]는 마지막 첫 니블로 선택한 대상의 FAULT/RUNNING/READY를 **실시간** 표시한다. 리셋 직후 대상은 A다. STATUS 데이터는 최종 명령 니블 직전의 대상 상태를 래치하며 bits[7:6]=0이다. 전역 reset/선택 해제가 프레임보다 우선한다. 이후 대상 불일치(3), 미정의 명령(3), 허용 상태 위반(2), 인자 형식 오류(3), FIFO 재시도(1), 성공(0) 순으로 판정한다. 불일치나 미정의 명령에는 더미 응답이 없다.

[추론] 한 번에 한 대상만 LOADING일 수 있다. 어느 쪽이든 RUNNING일 때 BEGIN/WRITE/END는 코드 2다. 상대가 LOADING이면 BEGIN·WRITE·END는 코드 2이고, 자기 LOADING에서 BEGIN은 재시작할 수 있다. 어느 쪽이든 LOADING이면 RUN은 코드 2다. 그 밖에는 v0.1 §6의 대상별 준비·오류 조건을 적용하므로 상대가 RUNNING인 동안 RUN도 가능하다. 허용 상태의 잘못된 길이·초과 WRITE·END 불일치는 코드 3, 대상 LOADING=READY=0, 기존 FAULT·FIFO 보존이다. STOP은 대상의 진행 중 적재만 취소한다. 상대가 실행 중일 때 fault난 이미지를 교체하려면 상대도 멈춘 후 BEGIN한다. TX/RX·STATUS에는 상대의 적재 잠금을 적용하지 않는다. 중단된 니블 프레임은 v0.1대로 전역 reset과 두 이미지 재적재로 복구한다.

### §9.5. 검증 경계

[추론] RTL 비교 경계는 dual_mode, exec_start_a/b, retire_a/b, pc_a/b[7:0], tx_pop_a/b, rx_push_a/b, tx_count_a/b[2:0], rx_count_a/b[2:0], fetch_valid, fetch_ctx, sram_addr[7:0], sram_we, instruction[15:0], instr_ctx, instr_valid다. a/b 표기는 _a와 _b 두 신호를 뜻한다. fetch_valid는 승인한 인출의 펄스, instr_valid는 소비 가능한 태그된 응답의 펄스다. 각각의 valid가 0일 때 그 ID를 비교하지 않는다. SRAM 쓰기 주소는 sram_we에서만, 읽기 주소는 fetch_valid에서만 비교한다. v0.1 §2의 단독 관측 이름과 의미도 유지한다. 두 컨텍스트가 같은 에지에 은퇴하면 실패다. GLS는 호스트 응답·출력·OE만으로 판정한다. 아래 벡터 K는 A의 RUN 수락 에지이고 홀수다. B의 RUN은 K+9(짝수)에 수락한다. A는 TLO 6, DELAY, DATA 0x10, OE 0x10, COMMIT 0x10, HALT이고 B는 v0.1 §7의 네 워드다. 각각의 워드 합은 0x8836과 0x3003이다.
