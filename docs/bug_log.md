# 검증 결함 기록

## V-001 · STOP 수락 에지의 잘못된 은퇴 펄스

| 항목 | 기록 |
|---|---|
| 명세 | §2에서 STOP 수락 에지에는 retire가 없다. §6에서 STOP은 같은 클록의 엔진 명령에 우선한다. [§2](../spec/spec.md#s2) · [§6](../spec/spec.md#s6) |
| 재현 입력 | 한 워드 `0x5000`(BR 0)을 적재해 RUN한다. RUN 수락 K 직후 STOP의 두 니블을 연속 전송하면 K+6 실행 에지에서 STOP을 수락한다. [재현 시험](../mutation/stop_witness.py) |
| 증상 | [실행 확인] 원본과 M15 양쪽에서 STOP 응답은 0이고 실행이 끝난다. 같은 에지 직후 원본 retire는 0, M15 retire는 1이다. 변이는 수정 전 코어 시험 5개를 모두 통과했다. [M15 사본](../mutation/M15/pe_core.v) · [변이 결과](../mutation/results.json) |
| 원인·검출 계층 | 당시 cocotb 회귀는 STOP 뒤의 상태를 검사했다. STOP이 명령과 겹치는 에지의 retire를 직접 검사해야 이 동작 차이를 구별한다. 원본 RTL은 해당 재현을 통과했다. |
| 수정 커밋 | `37963ca1189e088ff444d8dcf439d33fd5b70523`에서 [정규 STOP 회귀](../test/test.py#L246)를 추가했다. 원본은 BR 0과 대기 중 WAIT HIGH가 각각 STOP과 겹칠 때 모두 통과했다. M15는 새 시험에서만 실패했다. 실제 `(pc, exec_start, retire)`는 `(0, 1, 1)`, 기대값은 `(0, 0, 0)`이었다. [수정 전후 시험별 판정 및 XML SHA-256](../mutation/results.json) |

## V-002 · 호스트가 중단된 로더 프레임에 다음 명령을 전송

| 항목 | 기록 |
|---|---|
| 명세 | 중단된 니블 프레임은 리셋으로 복구한다. [§6](../spec/spec.md#s6) |
| 증상·재현 | [실행 확인] 커밋 `0e35d1d`에서 STATUS의 첫 REQ를 보낸 직후 GPIO 읽기에 `OSError` 또는 `KeyboardInterrupt`를 주입했다. 이어서 STOP을 호출하자 호스트가 `ui_in`에 0x10, 0x00을 차례로 썼다. 리셋을 다시 시도하다 중단한 경우에도 이전 세션이 살아 있었다. |
| 원인·수정 | 호스트가 ACK 만료만 처리해 I/O 예외가 불완전한 프레임을 남길 수 있었다. 명령과 더미 응답을 포함한 전송 중 예외가 나면 세션을 무효화하고 원래 예외를 전달한다. 리셋도 진입 시 세션을 무효화하고 ACK·상태가 0인 것을 확인하면 새 세션을 연다. [수정 커밋](https://github.com/jisung77/ttihp-protocol-engine/commit/b275e56e7142cde7bf9683466a8b29c0ea795178) |
| 검출 계층 | [실행 확인] Python 핀 회귀에서 수정 전 5개가 실패했다. 수정 후 모두 통과했고, 늦은 ACK 뒤에도 다음 명령은 핀을 쓰지 않았다. FIFO의 정상 재시도 응답 뒤에는 같은 세션에서 STATUS를 읽었다. [회귀 코드](../model/test_board_timeout.py) |

## V-003 · 듀얼 ISS에서 STOP의 상태가 한 클록 늦게 관측됨

[실행 확인] §6·§9.2에서 STOP은 수락 에지에 대상 PC·출력·OE를 지운다. COMMIT 다음 에지 E124에 STOP A를 수락했을 때 초기 ISS는 ACK와 정지 상태를 표시했지만 PC=3, 출력=OE=0x10이 남았다. 에지 관측을 마친 뒤 STOP을 적용한 것이 원인이었다. 수락을 에지 직전 상태로 판정한 뒤 RUN·STOP의 초기화를 같은 에지의 실행 관측 전에 적용했다. 수정 커밋 24e30c8d669618406ac9ea33c91b7e29eb4ad4b4에서 같은 입력의 E124 PC·출력·OE가 모두 0이었다. [독립 핀 검사](../model/test_v02_pins.py)

## V-004 · 듀얼 검사의 핀 소유권과 체크섬 공백

[실행 확인] RTL 기준 `0b4a2f8`에서 초기 회귀가 15개 주입 버그 중 13개를 검출했다. B가 A 소유 핀에 SHOUT하는 경우와 올바른 워드 수에 잘못된 END 체크섬을 보내는 경우가 빠져 있었다. §9.2와 §9.4에 따라 새 핀 검사를 추가했다. M05는 E358에 B가 계속 RUNNING인 것으로 나타났고, M12는 E430에 잘못된 이미지를 READY로 표시했다. 원본은 두 검사를 통과했다. 검증 수정 커밋은 `19dfe2b`이다. [보강 검사](../test/test_dual_faults.py) · [개별 판정과 원본 해시](../mutation/v02/results.json)

## 사람이 직접 확인할 지점

- 첫 REQ에서 중단한 직후 STOP을 호출했을 때 핀 쓰기 기록이 비어 있는지 확인한다.
- 정상 FIFO 재시도와 전송 중단이 서로 다른 복구 경로를 따르는지 확인한다.
