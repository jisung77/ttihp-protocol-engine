# 프로그래머블 프로토콜 엔진 v0.1 검증 계획

[추론] 단일 컨텍스트 MVP의 판정 기준은 [엔진 명세 v0.1](../spec/spec.md)이다. 아래 각 행의 절 번호는 자극·기대값·속성의 출처다. 구현이 기대값과 다를 때에는 명세와 첫 불일치 사이클을 먼저 확인한다.

[실행 확인] 단일 엔진의 RTL·ISS 차등 회귀, FIFO formal, UART·SPI 독립 검사, SRAM 포함 하드닝과 GLS를 실행했다. 초기 PC 범위 작업은 시간 제한에 도달했다. 후속 핀 관측기와 SRAM 읽기·적재 카운터·체크섬 추상화로 단독 및 듀얼 모드의 실행 중 PC 범위를 무한 깊이에서 증명했다. [후속 증명과 가정](../formal/README.md) [단일 엔진 검증 보고서](verification_report.md)

## 판정 시점과 독립성

[추론] RTL은 명세로 설계하고 VERIFY는 명세의 포트·모듈 경계로 ISS와 검사를 작성한다. 두 모델에 같은 외부 핀 자극을 준다. ISS는 동기화와 입력 이력을 독립 계산한다. 디지털 차등 시험에서는 샘플 에지와 입력 변경을 분리한다. 상승 에지 직전 값을 사용한 후 갱신된 PC·핀·FIFO 상태와 §2의 실행·은퇴 사건을 비교한다. 어셈블러의 바이너리 외에 손으로 인코딩한 명령도 사용한다. 첫 불일치와 직전 최대 20클록의 양쪽 trace, seed, 바이너리, 외부 입력을 저장한다. [§1](../spec/spec.md#s1) · [§2](../spec/spec.md#s2) · [§7](../spec/spec.md#s7)

## 명령·상태별 검사

[추론] 각 유효 조합을 최소 1회 관측하고 명세와의 불일치는 0건이어야 한다. 불가능한 조합에는 근거 절과 이유를 기록한다.

| 대상·근거 | 자극과 필수 판정 |
|---|---|
| 인출·은퇴 [§2](../spec/spec.md#s2) [§7](../spec/spec.md#s7) | RUN 승인 뒤 첫 인출 F와 S=F+1, 은퇴 R 뒤의 다음 인출 F=R+1을 비교한다. 정상 단일 클록 명령은 S=R이다. 정지 중에는 새 인출·중복 은퇴가 없어야 한다. SRAM 모델 교체 후 같은 타이밍 계약을 확인한다. |
| WAIT·DELAY [§4](../spec/spec.md#s4) | HIGH/LOW는 S에 이미 만족하면 성공한다. RISE/FALL 사건을 S−1, S, N=S+T, N+1에서 각각 발생시킨다. T=0·1·최댓값·무한을 검사한다. 유한 마지막 에지에서 사건과 기한이 겹치면 성공한다. 무한 대기에서 STOP·리셋으로 빠져나오는 경우를 넣는다. DELAY는 D=0·1·최댓값에서 R=S+D여야 한다. |
| 분기·오류 [§3](../spec/spec.md#s3) | 모든 opcode, 분기 조건 참·거짓, 루프 0·1·최댓값에서 다음 PC와 본문 횟수를 센다. 마지막 유효 주소, 잘못된 분기 목표·opcode·예약 비트에서 fault, OE 및 FIFO·시프트 부작용을 검사한다. |
| 핀·시프트 [§3](../spec/spec.md#s3) | 마스크 0·전체·일부에서 DATA/OE 준비 후 COMMIT 한 번으로 선택 비트만 같이 갱신되는지 검사한다. PULL·SRIMM·SHOUT은 OSR, SHIN·PUSH는 ISR 경로다. MSB/LSB 각각에 송수신 값이 다른 비대칭 바이트를 넣고 동작을 교대로 실행해 반대쪽 레지스터가 보존되는지 확인한다. |
| FIFO [§5](../spec/spec.md#s5) | 점유량 0·1·깊이−1·깊이, 포인터 랩, 동시 읽기·쓰기를 교차한다. 에지 직전 점유량으로 거래 허가를 예측한다. 막힌 PUSH/PULL은 PC·핀·OSR/ISR와 해당 포인터를 유지한다. 반대편 호스트 거래는 진행할 수 있고 재개한 엔진 명령은 한 번만 은퇴한다. |
| 로더·리셋 [§1](../spec/spec.md#s1) [§6](../spec/spec.md#s6) | 니블 순서·토글 ACK, 길이 0·1·256·257, 길이 오류 전후 FAULT·FIFO 보존, 개수·합 불일치, 부분 프레임과 재선택, 실행 중 쓰기 거절을 검사한다. 완전 적재 전 실행과 인출·쓰기 충돌은 0건이어야 한다. WAIT/FIFO 정지 중 STOP, 정지·전송·부분 적재 중 리셋/선택 해제와 재적재에서 PC·OE·FIFO·READY를 확인한다. |
| 첫 핀 예제 [§7](../spec/spec.md#s7) | 명세의 프로그램을 손으로 인코딩한 워드와 로더 바이트열 양쪽으로 재생한다. RUN 에지를 기준으로 명세의 각 인출·은퇴에서 PC·출력 데이터·OE를 원본 기대표와 대조한다. |

## 프로토콜과 검증 계층

| 검증 계층·근거 | [추론] 실행 방법과 통과 기준 |
|---|---|
| 독립 UART BFM [§8](../spec/spec.md#s8) | 8N1, 115200 baud에서 TX 핀으로부터 256종 바이트를 복원하고 RX는 BFM이 전송한 256종을 FIFO로 읽는다. 연속 프레임, TX 비트 폭 오차 ≤1%, RX 외부 baud −2/0/+2% 각각에서 4개 시작 위상을 검사한다. 위상 0은 클록 표본 채취 직후(0+)에 구동한다. 올바른 프레임의 데이터·프레이밍 오류 0건, 잘못된 정지 비트의 RX PUSH 0건을 요구한다. |
| 독립 SPI BFM [§3](../spec/spec.md#s3) [§8](../spec/spec.md#s8) | 마스터 DUT에 응답하는 독립 타깃을 연결한다. CPOL/CPHA 네 조합에서 유휴 레벨, 첫·마지막 에지, 샘플·변경 에지와 MSB 우선 비대칭 송수신 바이트를 확인한다. BFM은 지정 샘플 에지에서 비트를 복원하며 MOSI의 setup·hold 각각 ≥2클록을 검사한다. MISO는 그 에지 전후 각각 ≥3클록 안정시킨다. 50 MHz 가정에서 1 MHz SCK 반주기 25±1클록, CS setup·hold 각각 25클록 이상을 핀에서 검사한다. |
| CDC·속도 [§2](../spec/spec.md#s2) [§8](../spec/spec.md#s8) | 비동기 핀의 HIGH·LOW 폭과 위상을 바꾸고 보장 범위 밖의 좁은 펄스는 관측만 기록한다. 정확히 2클록 지연을 기대값으로 강제하지 않는다. 속도 표에는 동기화·검출·실행 경로, BFM 결과, 실제 P&R 타이밍을 함께 기록한다. |
| ISS·coverage [§1](../spec/spec.md#s1)~[§7](../spec/spec.md#s7) | 명령별 pytest, directed 후 유효 랜덤 프로그램을 수행한다. 초깃값은 고정 seed 32개×각 100회 은퇴다. 정상 프로그램은 대기 해제 자극을 포함한다. 의도한 영구 정지는 별도의 제한 시간 시험으로 확인한다. cocotb-coverage로 opcode·분기·FIFO 경계·리셋 직후·SPI 모드의 도달 가능한 bin 100%, 차등 불일치 0건을 요구한다. |
| formal [§2](../spec/spec.md#s2)~[§6](../spec/spec.md#s6) | SymbiYosys로 FIFO 넘침·고갈 금지, 순서, 점유/플래그, 허가된 동시 거래의 손실·중복 없음, 리셋 정의 상태, 허용된 PC 비순차 이동과 OE 갱신을 확인한다. 속성마다 근거 절, 환경 가정과 증명 모드를 기록한다. 핵심 경로 cover를 확인하고 깊이 제한 BMC의 결과는 해당 깊이로 표기한다. |
| BFM 호환성·GLS [§7](../spec/spec.md#s7) [§8](../spec/spec.md#s8) | cocotbext-uart·cocotbext-spi는 고정 버전으로 핀 방향, SPI 4모드, cocotb 호환성을 먼저 검사한다. 부족한 항목은 공개 프로토콜 규칙 기반의 독립 핀 모니터로 검증한다. 같은 프로젝트 커밋의 GLS에서 필수 예제의 핀 판정 기준을 재적용한다. |
| mutation·REVIEW [§1](../spec/spec.md#s1)~[§8](../spec/spec.md#s8) | 조건 반전·off-by-one·비트 순서·리셋값·FIFO 포인터 등 변이 15개를 각각 사본에 주입하고 근거 절·검출 시험·결과를 남긴다. 회귀에서 잡힌 유효 변이 수를 컴파일 가능하고 비등가인 대상 수로 나눈다. 컴파일 실패·입증된 등가·보류 변이는 따로 집계하고 유효 표본을 보충한다. 유효 15개에서 90% 이상은 최소 14개 검출이다. |
| 유연성 [§8](../spec/spec.md#s8) | UART·SPI로 MVP를 튜닝한다. I²C는 확장 승인 뒤 검토하고 PS/2는 ISA 동결 뒤 처음 시도할 held-out 대상으로 보관한다. 동결 RTL 해시가 같은 상태에서 프로그램만 변경했는지 확인한다. |

## 증거와 일정

[추론] 실행마다 입력 커밋, 도구 SHA, 실제 PDK와 설정, 명령·seed·종료 코드·기대 테스트 이름을 남긴다. XML의 이름별 1회 실행 및 실패·오류·스킵 0건을 검사하고 RTL과 GLS의 XML·로그·파형을 별도 보관한다. 하드닝 경고, resolved.json, pdk.json, GDS, 최종 넷리스트·metrics를 저장한다. CI run 링크, 실제 검사한 GDS의 SHA-256와 항목별 precheck 및 GLS 결과를 연결한다. [§8](../spec/spec.md#s8)

[실행 확인] 단일 엔진의 14일차 세 조건은 모두 통과했다. 아래는 평가에 사용한 기준이다. [검증 원본](https://github.com/jisung77/ttihp-protocol-engine/releases/tag/mvp-physical-38fffad) · [다음 단계인 두 컨텍스트의 시간표 실험](two_context_timing.md) [§8](../spec/spec.md#s8)

1. 실제 IHP SRAM이 포함된 GDS를 배치 인스턴스와 뷰로 확인하고, 그 산출물이 TT precheck의 필수 항목을 통과해야 한다.
2. UART TX가 독립 BFM에서 프레임과 비트 타이밍을 모두 만족해야 한다.
3. 100 × (배선 후 매핑된 표준셀 면적 + 하드 매크로 외곽 면적) / 동일 DEF·ODB의 8×4 코어 사각형 면적이 반올림 전 40% 이하여야 한다. 엔진·FIFO·로더·클록 트리·SRAM을 포함한다. filler·tap·endcap·decap은 제외하고 매크로 면적은 한 번만 센다.

[추론] 실패하면 확장을 보류하고 같은 기준으로 재실행한다. SRAM 실패는 단일 매크로 최소 설계에서 통합부터 확인한다. 래치 대안의 결과는 따로 기록한다. UART 실패는 첫 오류 프레임을 재현하고, 면적 초과는 FIFO 깊이·프로그램 용량 축소에 필요한 명세 변경과 영향을 제시한다. 2026-12-25까지 UART·SPI·어셈블러가 미완성이면 I²C를 문서상 확장으로 내린다. 2027-01-08 이후 RTL을 동결한다. 제출 차단 결함은 수정 영향과 재검증 범위를 기록한다. [§8](../spec/spec.md#s8)
