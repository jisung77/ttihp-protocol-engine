# 프로그래머블 프로토콜 엔진 검증 계획 초안

[미실행] 대상은 8×4 IHP에 탑재할 단일 컨텍스트 MVP다. 엔진의 RTL·ISS·formal·GLS 결과와 면적·속도 측정값은 아직 없다. 환경 점검용 덧셈기의 결과는 이 표의 통과 건수에 넣지 않는다.

[추론] 표의 W1 등은 [설계 결정표](spec_questions.md)의 항목 번호다. W1의 WAIT 우선순위와 최초 관측 클록은 사용자가 결정했다. 나머지 수치와 동작은 채택 전 권장안이다. 사람이 작성하는 `spec/spec.md`가 준비되면 각 행을 실제 절 번호에 연결하고, 정의가 비어 있는 행은 보류한다.

## 판정 시점과 독립성

[추론] RTL 담당은 명세와 포트 정의만 바탕으로 설계한다. VERIFY 담당은 RTL 소스를 열지 않고 문서화된 모듈 경계와 관측 신호를 사용한다. ISS는 독립적으로 명세를 해석하고 어셈블러가 출력한 바이너리를 읽는다. 손으로 인코딩한 명령 벡터도 포함해 어셈블러와 ISS가 같은 인코딩 오류를 공유하는 경우를 확인한다.

[추론] 두 모델에 같은 외부 핀 자극을 주고, ISS는 명세대로 동기화와 이력을 자체 계산한다. RTL에서 읽은 동기화 값을 골든 모델에 공급하지 않는다. 에지 직전 값으로 판정한 뒤 에지 이후 값이 안정되면 명세가 노출하는 상태를 비교한다. 디지털 차등 자극은 샘플 에지와 분리한다. 에지 근처 자극은 별도 CDC 위상 실험에서 다룬다. 실행 여부·은퇴 여부, PC, 핀 데이터·OE, FIFO 수락·반환 및 점유 상태를 대상에 둔다. 명세에 시뮬레이션용 모듈 경계 관측값으로 exec_start, retire, pc, tx_pop, rx_push 및 점유량을 제안한다. 실제 핀 배정은 소모하지 않는다. 명세에 채택되지 않은 내부 신호를 검사기가 임의로 참조하지 않는다. 첫 불일치 클록과 직전 최대 20클록의 양쪽 trace, seed, 프로그램, 외부 입력을 저장한다.

## 명령·상태별 검사

[추론] 아래는 directed 테스트와 기능 커버리지의 채택 제안이다. 각 유효 조합을 최소 1회 관측하고 명세와 불일치는 0건이어야 한다. 불가능한 조합은 이유와 근거 절을 남긴다.

| 대상 | 자극과 직접 판정할 내용 |
|---|---|
| W1·T1 WAIT | 실행 가능한 첫 클록을 S라 한다. HIGH/LOW는 S에 이미 만족하면 성공한다. 상승 에지가 S−1에만 있으면 무시하고 S에 있으면 성공한다. 하강 에지도 채택된 규칙을 반대 극성으로 시험한다. 유한 timeout T의 제안 구간은 [S, N]이고 마지막 클록은 N=S+T다. T=0·1·최댓값, 이벤트 없음, 마지막 클록 성공, 한 클록 늦은 이벤트를 대조한다. 무한 대기는 중지·리셋으로 탈출하는 경우를 넣는다. |
| T1 지연·인출 | DELAY D의 은퇴 R=S+D을 0·1·최댓값으로 검사한다. 다음 명령의 인출·실행 시점은 채택된 SRAM 지연을 각각 적용한다. 인출 응답 대기 중 중복 은퇴나 핀 변화는 0건이어야 한다. 실제 매크로 모델로 응답 시점을 다시 확인한다. |
| I1 분기·반복·오류 | 모든 opcode와 분기 조건의 참·거짓, 루프 0·1·최댓값에서 PC와 실제 본문 실행 횟수를 센다. 마지막 유효 주소의 다음 PC, 범위 밖 분기, 미정의 opcode의 오류·핀 안전 상태를 확인한다. |
| P1 마스크·핀·시프트 | 마스크 0·전체·일부, 출력값과 방향의 동시 변경, 변경 대상 밖 핀의 유지를 검사한다. MSB/LSB 양쪽에서 첫·마지막 비트가 다른 비대칭 값을 사용한다. 한 비트씩 시프트할 때마다 핀 순서·샘플 클록과 최종 바이트를 확인한다. |
| F1 FIFO PUSH/PULL | 비어 있음·1개·마지막 여유 슬롯·가득 참, 포인터 랩, 동시 읽기·쓰기를 교차한다. 수락 여부는 에지 직전 점유량으로 결정한다. 정지 중에는 해당 명령의 PC·시프트 값·핀을 유지하고, 반대편 호스트 거래는 독립적으로 진행한다. 재개한 명령은 한 번만 은퇴한다. |
| L1·R1 로더·리셋 | 부분·정상·잘못된 프레임, 적재 중 실행 요청, 실행 중 쓰기, 마지막 워드와 실행 시작의 경계를 구분한다. 인출과 쓰기의 동일 클록 충돌 0건, 완전 적재 전 실행 0건을 요구한다. WAIT·FIFO 정지·시프트·로딩 중 각각 리셋·선택 해제 후 재선택하여 PC·핀·OE·FIFO·프로그램 유효 상태와 재적재를 확인한다. |

## 프로토콜과 검증 계층

| 담당 | [추론] 실행 방법과 채택할 통과 기준 |
|---|---|
| 독립 UART BFM (D1) | 후보 형식은 8N1, 115200 baud다. TX는 외부 관측자가 시작·데이터 8비트·정지 비트를 복원하고, RX는 BFM이 생성한 프레임을 FIFO에서 읽는다. 바이트 256종을 양방향에서 확인하고 연속 프레임과 다수 시작 위상을 포함한다. 데이터·프레임 오류 0건, TX 비트 폭 오차 ≤1%, RX baud 편차 −2/0/+2% 각각에서 4개 시작 위상을 검사한다. 잘못된 정지 비트는 RX FIFO에 들어가지 않아야 한다. |
| 독립 SPI BFM (D1) | DUT는 마스터, BFM은 응답 타깃이다. CPOL/CPHA 4조합 모두에서 유휴 극성·첫 에지·샘플 및 변경 에지·마지막 에지를 핀에서 검사한다. 50 MHz 가정의 1 MHz SCK 반주기는 25±1클록, CS setup·hold는 각 25클록 이상을 후보로 둔다. 비대칭 TX/RX 바이트, CS setup·hold의 최소 경계와 연속 바이트에서 모든 관측값이 D1과 일치해야 한다. |
| CDC·속도 | 비동기 입력의 high·low 폭과 클록 대비 위상을 바꿔 명세상 보장 범위를 시험한다. 더 짧은 펄스는 관측 특성만 기록한다. 2FF의 아날로그 준안정성이나 절대 지연을 RTL 시뮬레이션으로 보증하지 않는다. 지원 속도 표에는 동기화·검출·실행 경로, 최소 펄스 폭, BFM 결과 및 실제 타이밍 결과를 구분한다. |
| ISS 차등·coverage | 명령군별 pytest와 directed 후 유효 랜덤 프로그램을 실행한다. cocotb-coverage로 명세에 연결된 bin을 수집한다. 초기 회귀 목표는 고정 seed 32개와 seed당 은퇴 100회다. 대기 해제가 가능한 자극을 함께 만들고, 의도한 정지는 별도 한정 시험으로 둔다. 비교 불일치 0건, 정의된 reachable bin 100%를 요구한다. 미관측 bin을 제외 처리하기 전에 directed를 추가한다. 멀티스레드·레인은 MVP 대상 밖이다. |
| formal | FIFO 넘침·고갈 금지, 순서 보존, 점유·full·empty 일치, 동시에 가능한 호스트·엔진 거래의 중복/손실 없음을 증명한다. 리셋 후 정의 상태, 명세가 허용한 경우만 PC 비순차 이동, OE는 허용된 핀 명령·리셋·안전 정지 사건에서만 갱신도 검사한다. SymbiYosys 속성마다 명세 절·가정·증명 모드를 남기고 핵심 경로 cover를 요구한다. 제한 깊이 BMC만 끝난 항목은 그 깊이와 한계로 기록한다. |
| BFM 호환성·GLS | 후보 cocotbext-uart·cocotbext-spi의 고정 버전이 핀 방향, SPI 4모드, cocotb와 호환되는지 짧은 독립 예제로 확인한다. 부족한 항목은 공개 프로토콜 규칙 기반의 독립 핀 모니터로 대체한다. GLS에서 채택된 필수 예제를 재실행하고 RTL과 동일한 프로토콜 판정을 적용한다. |
| mutation·REVIEW | 서로 다른 의도적 변이 15개를 사본에 주입한다. 조건 반전·off-by-one·비트 순서·리셋값·FIFO 포인터 등을 포함하고 각 행에 명세 절, 검출 시험, 결과를 남긴다. 분자는 회귀가 실제 잡은 유효 변이 수, 분모는 컴파일 가능하고 비등가인 대상 수다. 컴파일 실패·입증된 등가는 별도 집계하고 유효 표본을 보충한다. 분류 보류를 숨기지 않는다. 목표 90% 이상이며 유효 15개이면 최소 14개를 검출해야 한다. |
| 유연성 | UART·SPI 프로그램으로 MVP를 튜닝한다. I²C는 확장 승인 후 별도 기록한다. PS/2는 ISA 동결 뒤 처음 시도할 held-out 후보로 둔다. 그때 프로그램만 바꾼 실행과 동결 RTL의 동일 해시로 판정한다. |

## 증거와 단계 판정

[추론] 각 실행마다 프로젝트·도구 SHA, 실제 PDK와 설정, 명령·seed·종료 코드·기대 테스트 이름을 보관한다. XML에서는 이름별 1회 실행과 failure/error/skipped 0건을 확인한다. RTL과 GLS의 XML·로그·파형은 실행별 디렉터리에 둔다. 하드닝은 warnings, resolved.json, pdk.json, GDS, 최종 넷리스트·metrics를 보관한다. 공식 CI의 run URL·실제 커밋·검사한 GDS의 SHA-256·항목별 precheck 및 GLS 결과를 연결한다.

[미실행] 14일차 세 조건은 따로 판정한다. 증거가 없으면 미판정으로 둔다.

1. 실제 IHP SRAM 매크로가 들어 있는 GDS임을 배치 인스턴스·뷰로 확인하고 해당 산출물의 TT precheck 필수 항목이 통과해야 한다. 래치 대안은 별도 결과로 분류한다.
2. UART TX가 독립 BFM에서 D1 프레임과 비트 타이밍을 만족해야 한다.
3. A1 기준 점유율은 100 × (배선 후 표준셀 면적 + 하드 매크로 면적) / 동일 8×4 배치 코어 사각형 면적이다. 분자에는 엔진·SRAM·FIFO·로더와 클록 트리 셀을 포함하고 filler/tap/endcap/decap은 제외한다. 매크로 면적은 한 번만 센다. 분모는 동일 DEF/ODB의 코어 경계로 계산한다. 반올림 전 값이 40% 이하여야 한다.

[추론] 기본 엔진을 완성하고 게이트를 통과한 뒤에만 2~4개 컨텍스트의 파이프라인 공유와 UART·SPI 동시 실행을 첫 확장으로 검토한다. 다음 순서는 I²C와 CRC다. 한 조건이라도 실패하면 확장을 보류한다. SRAM 실패는 단일 매크로 최소 설계에서 통합을 분리하고, UART 실패는 한 채널 파형의 첫 오류를 줄인다. 면적 초과는 FIFO 깊이·프로그램 용량 등 후보를 줄여 같은 세 기준으로 재검증한다. 2026-12-25에 UART·SPI·어셈블러가 미완성이면 I²C를 문서상 확장으로 내린다. 2027-01-08 이후 RTL을 동결하고 GLS·문서를 우선한다. 제출을 막는 결함은 영향과 재검증 범위를 기록한다.

## 사람이 직접 확인할 지점

- W1의 첫·마지막 판정과 성공 우선순위가 명세의 타이밍 그림과 일치하는가?
- 핀·FIFO 관측 경계와 D1 허용 편차가 RTL을 읽지 않아도 외부 검사기로 판정할 만큼 구체적인가?
- 실행 전에 A1 면적 정의와 mutation 제외·보충 조건을 고정했는가?
