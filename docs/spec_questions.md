## W1. WAIT는 어느 시점의 사건을 인정하는가?

**사용자 확정.** [미실행] 아래는 합의한 엔진 기대 동작이다. 첫 판정 클록 S는 유효한 WAIT가 실행되는 상승 에지다. 그 에지 직전에 실행부에서 보이는 동기화된 레벨 또는 에지 검출값을 판정한다. 이미 참인 레벨은 S에서 성공한다. RISE는 S부터 보이는 새 상승 사건을 인정한다. 마지막 허용 클록도 포함하며 성공 판정을 타임아웃보다 먼저 한다. 아래 표는 리셋·STOP·주소 오류가 없는 정상 실행 조건이다.

| 실행부에서 본 순서 | 기대 결과 |
|---|---|
| S−1에서만 상승 사건이 있었고 S에서도 HIGH 유지 | RISE는 계속 대기한다. 같은 조건에서 HIGH 대기는 S에 성공한다. 단, S가 기한이면 RISE는 타임아웃이다. |
| S에서만 상승 사건이 보임 | S에서 성공 |
| 마지막 허용 클록 N에서 사건과 만료가 동시에 성립 | N에서 성공 |
| N 직후에 검출 레지스터가 바뀌어 N+1에 처음 보임 | N에서 이미 타임아웃 |

[미실행] RISE가 S에서만 보이는 예의 타이밍 그림이다. 검출값은 각 상승 에지 직전의 값이다.

| 클록 에지 | S−1 | **S** | S+1 |
|---|---|---|---|
| WAIT 명령 | 실행 전 | **실행 시작·첫 판정** | 이미 완료 |
| 실행부의 상승 검출값 | 0 | **1** | 0 |
| 해당 WAIT의 성공 은퇴 | 0 | **1** | 0 |

## T1. 한 명령은 몇 클록을 쓰는가?

[추론] 상승 에지에서 상태를 갱신한다. S는 실행 시작, R은 해당 명령이 완료되어 상태를 한 번 반영하는 에지다. 대기 중에는 같은 명령을 다시 시작하지 않는다.

| 질문 | 권장 결정과 경계값 |
|---|---|
| SRAM에서 다음 명령은 언제 오는가? | 단일 포트·동기 읽기·비중첩 인출을 쓴다. 일반 명령은 S=R, 다음 요청은 R+1. 매크로가 요청 뒤 한 주기 안에 읽기 데이터를 제공하면 다음 S는 R+2다. 실제 모델의 지연을 확인해 명세와 속도표를 동결한다. |
| WAIT 시간값 0과 1은? | 유한 값 T는 S 뒤에 추가로 허용할 클록 수다. 기한 N=S+T. T=0은 S 한 번, T=1은 S와 S+1을 본다. 무한 대기는 별도 비트로 선택한다. 대기 종료 때에만 성공/타임아웃 플래그와 PC를 반영한다. |
| DELAY 시간값 0과 1은? | D는 실행 뒤 추가로 기다릴 클록 수다. R=S+D. D=0은 S에서, D=1은 S+1에서 완료한다. 다음 명령의 인출 시간은 별도다. |
| 2FF와 펄스 폭은? | 핀마다 2FF를 거친 값으로 레벨과 에지를 만든다. 이력은 명령 정지 중에도 갱신한다. 리셋 후 첫 유효 샘플은 이력 초기값으로 사용한다. 초기 HIGH만으로 가짜 RISE를 만들지 않는다. HIGH와 LOW를 각각 3 설계 클록 이상 유지하는 입력부터 위상 스윕한다. 이는 초기 검증 범위이며 실리콘 최소 펄스 폭은 별도 측정 사항이다. |

## I1. 어떤 상태와 명령을 두는가?

[추론] 한 컨텍스트에 프로그램 **256워드 × 16비트**, 워드 주소 PC 8비트, 시프트 레지스터와 루프 카운터 각 8비트, 시간 레지스터 16비트를 권한다. 논리 저장량은 256×16=4,096비트다. 프로그램 길이는 256을 표현할 수 있게 9비트로 유지한다. 우선 IHP 단일 포트 SRAM을 사용한다. 동일 PDK 리비전의 동작 모델·LEF·Liberty·GDS·전원 연결을 대조한 뒤 실제 매크로를 선택한다. [주최 측 SRAM 안내](https://blog.janestreet.com/protocol-emulator-asic-competition/) · [CMOS5L 통합 사례](https://kdp1965.github.io/ihp-um-janestreet-prism/ihp_sram_macro.html)

[추론] 16비트 한 워드에 5비트 연산 코드와 11비트 인자를 둔다. 데이터·방향 준비, 마스크 적용, 시간값 상·하위 바이트 설정, WAIT, DELAY, 시프트 입·출력, 분기, 루프 설정·감소 분기, FIFO PUSH/PULL, 정상 정지를 명령군으로 삼는다. WAIT는 단일 핀의 HIGH/LOW/RISE/FALL 및 유한/무한 대기를 선택한다. 분기는 무조건·WAIT 성공·WAIT 타임아웃·루프 0을 검사할 수 있게 한다. 아래 인코딩을 채택안으로 둔다. 각 워드는 [15:11] opcode, [10:0] 인자다. 사용하는 필드 외의 비트는 0이며 위반하면 fault다.

| opcode (16진수) | 인자·효과의 권장 인코딩 |
|---|---|
| 00 HALT, 0D PUSH, 0E PULL | 인자 0. 정상 정지, SR→RX, TX→SR 순이다. |
| 01 DATA, 02 OE, 03 COMMIT | [7:0]은 각각 준비 데이터, 준비 OE, 두 준비값에 적용할 마스크다. |
| 04 TLO, 05 THI, 07 DELAY | TLO·THI는 [7:0]으로 시간 레지스터의 해당 바이트만 쓴다. DELAY 인자는 0이며 시간 레지스터를 D로 쓴다. |
| 06 WAIT | [2:0] 핀, [4:3]은 LOW/HIGH/RISE/FALL=0/1/2/3, [5]는 무한 대기. 유한이면 S에서 시간 레지스터를 T로 사용한다. FALL에도 W1의 관측 창을 대칭 적용한다. |
| 08 SHIN, 09 SHOUT | [2:0] 핀, [3]은 MSB 우선=0·LSB 우선=1이다. |
| 0A BR, 0B LSET, 0C DJNZ, 0F SRIMM | BR [9:8]은 무조건/성공/타임아웃/루프0=0/1/2/3, [7:0]은 절대 주소다. LSET·SRIMM은 [7:0] 즉시값을 쓰며 DJNZ의 [7:0]은 절대 주소다. |

[추론] 감소 분기는 이전 카운터가 0이면 0을 유지하고 다음 명령으로 간다. 이전 값이 양수면 1을 빼고 새 값이 양수일 때만 목표 주소로 간다. 따라서 1은 0으로 바뀌고 분기하지 않는다. 본문 0회 실행에는 진입 전 0 분기를 쓴다. PC+1과 분기 목표는 적재 길이와 비교한 뒤 PC에 쓴다. 마지막 주소에서 순차 실행하면 fault로 안전 정지한다. HALT에는 다음 주소가 필요 없다. 선택된 다음 PC의 유효성을 부작용보다 먼저 판정한다. 불법 명령·예약 인자·범위 밖 목표도 fault로 정지하고 해당 명령의 FIFO·시프트 부작용은 발생시키지 않는다.

## P1. 핀과 시프트는 언제 바뀌는가?

[추론] 호스트는 ui/uo, 프로토콜 엔진은 uio 8개를 소유한다. 출력 데이터와 OE에 각각 준비 레지스터를 두고 마스크 적용 명령의 R에서 선택한 비트의 데이터·OE를 함께 반영한다. 마스크 0은 둘 모두 유지한다. 개별 비트의 외부 전기적 전환 시차는 별도 측정한다.

[추론] SHOUT은 선택한 핀에 이전 시프트 값의 bit7(MSB 우선) 또는 bit0(LSB 우선)을 R 직후 출력하고, 해당 방향으로 한 자리 밀며 0을 채운다. 해당 핀의 준비 데이터도 갱신해 나중 마스크 적용 때 과거 값이 되살아나지 않게 한다. OE는 유지한다. SHIN은 R 직전 동기화 표본을 받아 MSB 우선이면 왼쪽으로 밀고 bit0에, LSB 우선이면 오른쪽으로 밀고 bit7에 넣는다. 8회 뒤 바이트를 비교한다.

## F1. FIFO가 막히면 무엇이 유지되는가?

[추론] TX·RX는 각각 4바이트 FIFO를 권한다. 호스트가 TX에 쓴 바이트는 엔진 PULL로 시프트 레지스터에 들어간다. 엔진 PUSH는 시프트 값을 RX에 복사한다. 에지 직전 점유량으로 요청을 허가한다. 가득 찬 FIFO에서 같은 에지에 읽기가 허용돼도 쓰기는 다음 클록부터 허용한다. 빈 FIFO에 쓰기가 들어온 에지에서 읽기는 다음 클록까지 기다린다. 중간 점유량에서는 양쪽 성공 시 FIFO 순서를 유지하고 점유량은 같다.

[추론] 엔진 요청이 막히면 PC·시프트 값·플래그·출력·해당 엔진측 포인터는 유지한다. 호스트측 허가된 전송과 동기화 이력은 계속 진행한다. 해제 시 정확히 한 번만 전송한다. 호스트의 TX-full/RX-empty 요청에는 재시도 응답을 주고 그 요청의 큐 효과는 없다. 무한 WAIT나 FIFO 정지에서도 로더의 STOP은 엔진을 정지시킬 수 있다.

## L1. RP2350은 프로그램을 어떻게 적재하는가?

[추론] ui[3:0]은 호스트 데이터, ui[4]는 요청 토글, ui[7:5]는 0이다. uo[3:0]은 응답 니블, uo[4]는 확인 토글, uo[5]·uo[6]·uo[7]은 각각 READY·RUNNING·FAULT다. 요청은 2FF로 동기화한다. 호스트는 요청 전부터 확인을 받을 때까지 니블을 유지한다. 확인 토글이 요청과 같아진 후 다음 니블을 보낸다. 응답 데이터는 다음 확인까지 유지한다.

[추론] 고정 로더 프레임은 명령 바이트와 명령별 고정 길이 페이로드를 사용한다. 바이트는 상위 니블 먼저, 16비트 길이·데이터는 하위 바이트 먼저 보낸다. BEGIN(길이 1~256) → WRITE(워드, 순차 주소) 반복 → END(16비트 합 검산) 순서다. 합은 전송한 16비트 워드 합의 하위 16비트다. 중복 검출이나 암호학적 무결성을 보장하지 않는다. 개수와 합이 맞는 END에서만 READY가 된다. RUN은 READY에서만 PC=0으로 시작한다. 실행 중에는 TX/RX·상태 조회·STOP만 받고 SRAM 쓰기는 거절한다. BEGIN은 유효성·진행 주소·FIFO를 초기화한다. 길이 초과, 적재 중 초과 WRITE, 개수 불일치 또는 검산 실패는 적재를 취소하고 READY=0으로 둔다. READY는 완전한 이미지가 유효하다는 뜻으로 RUNNING 중에도 1이다. LOADING에서만 로더가 SRAM을 쓰고, RUNNING에서만 엔진이 읽는다. 정지 상태에서는 둘 다 요청하지 않는다. RUN 승인 에지 다음 클록부터 첫 인출을 허용한다.

[추론] 로더 명령 바이트 후보는 00 STATUS, 01 BEGIN(길이 2바이트), 02 WRITE(1워드), 03 END(합 2바이트), 04 RUN, 05 STOP, 06 TX(1바이트), 07 RX다. 마지막 요청 니블을 확인할 때 응답 코드 0=성공, 1=FIFO 재시도, 2=상태상 거절, 3=형식/길이/합 오류를 반환한다. 성공한 STATUS·RX는 뒤따르는 더미 니블 0 두 개에 결과의 상·하위 니블을 차례로 반환한다. RX는 명령 승인 시 한 번만 pop하고 응답을 보관한다. STATUS는 bit0=TX 여유, 1=RX 데이터 있음, 2=READY, 3=RUNNING, 4=FAULT, 5=LOADING, 7:6=0이다. STOP도 명령 바이트 경계에서만 해석한다. 프레임 도중 멈춘 호스트는 리셋 후 다시 적재한다. 알 수 없는 명령 바이트는 페이로드 없이 형식 오류를 응답하고 다음 명령을 기다린다. 금지 상태의 명령도 정의된 페이로드 끝까지 소비한 뒤 거절한다.

[추론] 손계산 예를 들면 SRIMM 0x96과 HALT 두 워드는 0x7896, 0x0000이다. 호스트 바이트열은 BEGIN `01 02 00`, 두 번의 WRITE `02 96 78`과 `02 00 00`, END `03 96 78`, RUN `04`다. 각 바이트마다 상위 니블을 먼저 보낸다. 이는 프레임 형식을 점검하기 위한 예다.

## R1. 리셋·정지·선택 해제는 어떤 상태를 만드는가?

[추론] rst_n은 비동기 assert·동기 release를 권한다. 리셋/선택 해제 시 OE와 출력 데이터는 0, PC·FIFO·시프트·카운터·플래그·로더 프레임은 초기 상태, 프로그램 유효 표시는 0이다. SRAM 셀 초기값에 의존하지 않는다. 호스트는 재선택 후 요청 토글 0으로 정렬하고 완전히 재적재한다. 우선순위는 리셋·선택 해제 → 호스트 STOP → 명령 처리다. STOP은 대기를 취소하고 OE를 0으로 만들며 FIFO를 비운다. 완료된 프로그램의 유효 표시는 유지한다. 정상 HALT는 마지막 RX 바이트를 읽을 수 있게 FIFO를 보존하고 OE를 해제한다. 같은 에지에 STOP과 FIFO 요청이 겹치면 STOP이 이겨 FIFO는 초기화되고 명령은 은퇴하지 않는다. fault는 OE를 해제하고 실행을 막는다. 새 BEGIN은 정지 상태에서 fault와 프로그램 유효 표시를 해제한다. 로딩 중 STOP은 부분 이미지를 폐기한다. RUN은 정지·READY·무오류일 때 PC·핀·준비값·SR·루프·시간·WAIT 플래그를 0으로 초기화한다. 미리 채운 TX를 포함해 FIFO와 동기화 이력은 RUN에서 보존한다. 리셋 시에는 이들 FIFO와 이력의 유효 표시도 초기화한다.

## D1. UART와 SPI에서 어떤 속도를 먼저 노리는가?

[추론] 단일 엔진에서 UART TX/RX 각각 8N1, 115,200 baud, SPI 마스터 모드 0~3은 SCK 1 MHz를 초기 후보로 삼는다. 설계 클록을 50 MHz로 가정할 때 UART는 50,000,000÷115,200≈434.03클록/비트, SPI 반주기는 50,000,000÷(2×1,000,000)=25클록이다. 프로그램은 인출·실행 시간을 포함해 지연을 계산한다. 목표 속도는 P&R 타이밍과 핀 관측으로 확인한다.

[추론] UART RX는 동기화된 시작 하강을 검출한 뒤 시작 비트 중앙에서 LOW를 재확인하고, 이상적인 시작 에지 기준 1.5비트부터 데이터 중앙을 겨냥한다. 정지 비트 LOW인 프레임은 프로그램이 PUSH하지 않는다. 첫 합격선 후보는 TX 비트 폭 오차 1% 이하, RX 외부 baud 편차 −2%, 0, +2%에서 정상 프레임의 바이트 오류 0건이다. 각 편차에서 시작 위상 0·¼·½·¾ 설계 클록을 검사한다. SPI는 CPOL로 유휴 레벨을 정한다. 선행 에지는 유휴 레벨에서 벗어나는 에지다. CPHA=0은 선행 에지에서 샘플하므로 첫 MOSI 비트를 먼저 내보낸다. CPHA=1은 선행 에지에서 변경하고 후행 에지에서 샘플한다. 초기 속도 시험은 의도한 SCK 반주기 25클록에서 ±1클록 이내를 검사한다. CS는 active-low이며 첫 에지 전 setup, 마지막 에지 뒤 hold에 각각 최소 반주기를 둔다. 동기화된 MISO로 원래 샘플 시점의 비트를 구별할 수 있는지는 위상·지연을 바꾼 BFM으로 확인한다.

## A1. 14일차의 40%는 어떻게 계산하는가?

[추론] 분모는 정해 둔 8×4 배치의 실제 배치 코어 사각형 면적(동일 DEF/ODB 바닥계획)이다. 분자는 배치·배선 후 엔진 전체의 매핑된 표준셀·클록 버퍼 면적과 하드 매크로 외곽 면적의 합이다. FIFO·로더·SRAM을 포함하며 filler·tap·endcap·decap은 제외한다. 매크로 내부 셀은 중복 집계하지 않는다. 같은 단위로 100×분자÷분모 ≤40을 판정한다. 면적·WNS는 실측 때 기입한다.

## 두 컨텍스트 RTL 전에 결정할 항목

[실행 확인] 단일 엔진의 14일차 세 조건이 충족돼 UART TX와 SPI 마스터의 동시 시간표를 시험했다. 아래는 v0.2 후보의 미결 사항이다. [가정과 핀 측정값](two_context_timing.md)

| 결정할 질문 | [추론] 검토할 후보와 수용 시험 |
|---|---|
| WAIT·DELAY·FIFO가 다른 스레드의 슬롯에서 완료 가능해지면 어느 클록에서 무엇을 바꾸는가? | WAIT는 매 클록 동기화된 사건을 보고 기한과 겹치면 성공을 보관한다. 후보에서는 다음 자기 실행 슬롯에서 한 번만 은퇴한다. S−1·S·N·N+1 및 보관 중 STOP·reset을 시험한다. 홀수 D인 DELAY에서 자기 슬롯 은퇴와 §4의 R=S+D가 다른 경우, 듀얼 모드 계약과 FIFO의 실제 수락·포인터 변경 에지를 함께 정한다. |
| 하나의 SRAM으로 프로그램을 어떻게 나누고 적재하는가? | 실험은 128워드씩 고정 분할했다. 분기 인코딩은 그대로 두고 물리 인출 주소를 base+PC로 계산하는 안을 검토한다. 실제 로더에서는 컨텍스트 선택, 길이 경계, RUN 중 쓰기·읽기 충돌, v0.1의 256워드 이미지 호환 모드를 결정한다. 두 영역의 마지막 주소 및 경계 밖 분기를 시험한다. |
| 어느 컨텍스트가 핀·FIFO를 소유하고 STOP·FAULT는 어디까지 영향을 주는가? | 겹치지 않는 핀 마스크와 컨텍스트별 TX/RX를 후보로 둔다. 호스트 조회 대상, 충돌 거절, 전체 리셋과 개별 STOP의 우선순위를 명시하고 한쪽의 정지·포화 중 다른 쪽 핀의 연속성을 검사한다. |
| v0.1과 동시 실행 모드를 어떻게 구별하는가? | 단독 실행에서는 기존 바이너리의 F·S·R 및 UART/SPI 파형을 보존한다. 두 모드의 로더 선택 방식, 읽기 응답 태그, 매 클록 SRAM 포트 한 번·공용 실행부 한 번을 검증할 관측 신호를 정한다. |
| 동시 프로그램의 통신 속도를 어떻게 판정하는가? | SPI는 50 MHz에서 24/26 duty, 반주기 25±1, 한 주기 50, CS setup/hold ≥25를 함께 검사한다. UART는 시작 에지 기준 각 전이의 위치와 비트 폭 오차를 모두 검사한다. |

## 다음 확장 후보 · I²C 마스터

[실행 확인] v0.2 정본에는 I²C 전송이나 CRC 계약이 없다. [추론] 아래는 기존 ISA로 실행할 마스터 프로그램의 범위를 정하기 위한 질문이다.

[실행 확인] 1바이트 쓰기, 두 종류의 NACK, 무기한 SCL 대기에 대한 단독 모드 응용 예제를 검증했다. 읽기·반복 START·CRC는 여전히 열린 항목이다. [예제 범위와 판정 근거](../experiments/i2c_write/README.md)

1. **전송과 응답** — 7비트 주소 쓰기·읽기, 반복 START를 쓰는 결합 전송 중 어떤 예제를 지원할까? 주소 또는 쓰기 데이터가 NACK이면 마스터는 어떻게 종료하고 호스트에 무엇을 알릴까? 읽기에서는 어느 바이트까지 ACK하고 언제 마지막 NACK·STOP을 보낼까?
2. **오픈드레인과 클록 스트레칭** — SDA·SCL에서 LOW는 출력값 0과 OE=1로 구동하고 해제는 OE=0으로 표현할 때, SCL 해제 뒤 실제 핀 HIGH를 어느 동기화 표본에서 인정할까? 외부 장치가 SCL을 LOW로 유지할 때 대기 기한의 시작·종료와 만료 후 두 선의 상태는 어떻게 정할까?
3. **핀 기반 판정과 속도** — 독립 버스 모델은 양측의 LOW 구동을 합친 SDA·SCL에서 어떤 START·STOP, 8개 데이터 비트와 9번째 ACK/NACK를 복원할까? 목표 속도에서 SCL의 최소 HIGH·LOW 폭과 SDA의 setup·hold를 어떤 단위로 판정하고, 2FF·명령 지연을 고려해 어느 입력 위상을 시험할까? 보드의 핀 배선·외부 풀업 저항·부하에 따른 상승 시간은 물리 실험 조건으로 따로 기록한다.
4. **선택적 CRC** — 예제의 상위 프로토콜이 CRC를 요구하는가? 요구한다면 그 프로토콜이 지정한 폭·다항식·초깃값·입출력 비트 반사·최종 XOR·계산에 포함할 바이트·기대값이 있는 검사 벡터는 무엇인가?
